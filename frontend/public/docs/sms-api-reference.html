Public Send Endpoint

Use the public SMS API when your ERP, CRM, website, or backend service needs to send SMS through Textzy. The external request stays simple while Textzy handles provider routing, DLT validation, audit logging, and ledger entry creation.

GET/api/public/messages/send
POST/api/public/messages/send

GET Request

https://api.textzy.in/api/public/messages/send?recipient=919999999999&msg=Your approved DLT message text&user=MONEYART&pswd=YOUR_PASSWORD&apikey=YOUR_API_KEY&channel=sms&sender=MNYART&PE_ID=1601100000000006533&Template_ID=1207171593687982329&tenantSlug=moneyart

POST Request

{
  "recipient": "919999999999",
  "message": "Your approved DLT message text",
  "user": "MONEYART",
  "password": "YOUR_PASSWORD",
  "apiKey": "YOUR_API_KEY",
  "tenantSlug": "moneyart",
  "channel": "sms",
  "sender": "MNYART",
  "peId": "1601100000000006533",
  "templateId": "1207171593687982329",
  "idempotencyKey": "sms-20260311-0001"
}
For India DLT traffic, sender, PE_ID, Template_ID, and the final message text must match your approved records exactly.

Request Fields

Each tenant has its own username, password, API key, and optional IP whitelist. Credentials are isolated per tenant.

Registry Endpoints

Keep approved sender IDs and DLT templates centralized before your applications start sending traffic.

GET/api/sms/templates
POST/api/sms/templates
POST/api/sms/templates/import-approved-csv
GET/api/sms/senders
POST/api/sms/senders
Recommended approach: register sender IDs first, import approved DLT templates second, then use the public send endpoint for live traffic.

Authentication Model

  • tenantSlug is mandatory.
  • Credentials are validated against that tenant only.
  • Optional IP whitelist can be enforced per tenant.
  • HTTPS is required in production.

Delivery Statuses

acceptedTextzy accepted the request and queued it for the configured SMS route.
queued / sentUpstream provider processing is in progress.
deliveredFinal delivery confirmation received.
failed / rejectedUpstream or compliance rejection.

Segment Rules

  • English GSM: 1-160 chars = 1 SMS, multipart uses 153 chars per segment.
  • Unicode / regional: 1-70 chars = 1 SMS, multipart uses 67 chars per segment.

Implementation Checklist

  • Generate tenant API credentials in Integrations.
  • Save sender IDs and approved templates.
  • Use idempotency keys for retry-safe sends.
  • Monitor tenant delivery report and SMS ledger.
  • Enable IP whitelist when traffic originates from fixed server IPs.
