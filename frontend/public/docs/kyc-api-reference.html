KYC API Reference

Tenant-scoped KYC session API with DigiLocker plugin flow: create session, redirect end-user for consent, handle callback, deliver webhook, and charge per successful verification via KYC credits.

Base URL: https://api.textzy.in Metric: digilockerKyc (KYC credits)

Endpoints

POST/api/kyc/sessions
GET/api/kyc/sessions/{sessionId}
GET/api/kyc/sessions?take=50
POST/api/public/kyc/sessions
GET/api/public/kyc/sessions/create?tenantSlug=...&user=...&pswd=...&apikey=...&docType=PAN
GET/api/public/kyc/digilocker/callback?sessionId=...&code=...&state=...
For customer integrations (API key auth), the same tenant endpoints are supported using X-API-Key/X-API-Secret plus X-Tenant-Slug.

Simple Public API (Like SMS)

Use the same credential style as the SMS public API: tenantSlug, user, password/pswd, apiKey/apikey.

POST/api/public/kyc/sessions
{
  "tenantSlug": "moneyart",
  "user": "MONEYART",
  "password": "YOUR_PASSWORD",
  "apiKey": "YOUR_API_KEY",
  "provider": "digilocker",
  "docType": "PAN",
  "customerRef": "user-123",
  "successRedirectUrl": "https://yourapp.com/kyc/success",
  "failureRedirectUrl": "https://yourapp.com/kyc/failure",
  "webhookUrl": "https://yourapp.com/webhooks/textzy-kyc"
}

Response

{
  "sessionId": "GUID",
  "provider": "digilocker",
  "status": "created",
  "docType": "PAN",
  "redirectUrl": "https://digilocker.../authorize?...",
  "state": "..."
}
Redirect the end-user to redirectUrl to complete DigiLocker consent/login.

Create Session

POST/api/kyc/sessions
{
  "provider": "digilocker",
  "customerRef": "user-123",
  "docTypes": ["PAN", "DL"],
  "successRedirectUrl": "https://yourapp.com/kyc/success",
  "failureRedirectUrl": "https://yourapp.com/kyc/failure",
  "webhookUrl": "https://yourapp.com/webhooks/textzy-kyc"
}
If webhookUrl is omitted/empty, Textzy uses the tenant default kycWebhookUrl (configure once in Integrations).

Response

{
  "sessionId": "GUID",
  "provider": "digilocker",
  "status": "created",
  "redirectUrl": "https://digilocker.../authorize?...",
  "state": "..."
}
Redirect the end-user to redirectUrl to complete DigiLocker consent/login.

Webhook Delivery

If webhookUrl is set (or tenant default kycWebhookUrl is configured), Textzy POSTs a payload when the session completes.

{
  "sessionId": "GUID",
  "tenantId": "GUID",
  "provider": "digilocker",
  "status": "verified",
  "ok": true,
  "customerRef": "user-123",
  "requestedDocTypes": ["pan", "dl"],
  "failureReason": "",
  "completedAtUtc": "2026-03-16T00:00:00Z",
  "result": {
    "provider": "digilocker",
    "requestedDocTypes": ["pan", "dl"],
    "documentTypes": ["PAN", "DL"],
    "issuedDocsStatus": 200,
    "issuedDocs": {}
  }
}
Access tokens are never included in webhook payloads.

Credits

  • Metric key: digilockerKyc
  • Consumed only on verified.
  • Units per success: Integration Catalog per-plugin setting (preferred), fallback digilocker.creditsPerSuccess (default 3).

docTypes and OAuth

docTypes is a business-level list used to request specific document categories (for example PAN, Aadhaar, DL). Textzy passes these to DigiLocker using the configured requester parameter (default req_doctype).

  • Examples: PAN, AADHAAR, DL, RC, PASSPORT
  • scope is different: it is the OAuth scope (typically files.issueddocs) configured at platform level.
One session = one docType: Textzy can charge different credits per docType. Create one KYC session per docType for predictable billing.
Authorize URL and Token URL are OAuth2 endpoints. They are platform-level (platform owns DigiLocker client credentials) and are not configured per request. In Platform Settings, you can leave them blank to use default DigiLocker endpoints.
Aadhaar / extended flows: DigiLocker may require extra authorize query params (e.g. dl_flow=signin&acr=aadhaar&amr=aadhaar+exists_ac_pin). Configure these in Platform Settings → DigiLocker Master Config → Authorize Extra Params. If DigiLocker asks for additional scopes like openid or userdetails, set them in the platform Scope field.

API Key Headers

  • X-Tenant-Slug
  • X-API-Key
  • X-API-Secret
curl -X POST "https://api.textzy.in/api/kyc/sessions" \
  -H "Content-Type: application/json" \
  -H "X-Tenant-Slug: moneyart" \
  -H "X-API-Key: ***" \
  -H "X-API-Secret: ***" \
  -d "{\"provider\":\"digilocker\",\"customerRef\":\"u-1\",\"docTypes\":[\"PAN\"]}"
