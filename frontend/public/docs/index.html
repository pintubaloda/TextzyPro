Quick Integration Rules

Keep the same request format you already use today. This page just gives it a cleaner, more professional developer experience.

  • Use tenant-scoped public credentials exactly as issued by the platform.
  • Send one KYC doc type per session request.
  • Always pass customerRef when you want traceability in reports.
  • Use status + file endpoints to complete the KYC lifecycle.
1

Generate tenant credentials

Use the platform-issued tenant slug, user, password, and API key exactly as provided.

2

Pick the right endpoint

Use SMS or WhatsApp for messaging, DigiLocker for redirect-based KYC, and GST for instant AppyFlow verification.

3

Track customer reference

Always send customerRef for easier reconciliation in both customer and platform reports.

4

Poll status + files

Use the session status endpoint to fetch final result data and available KYC file identifiers.

SMS Send

Send a DLT-compliant SMS using tenant credentials with the public API format already used across your integrations.

POSThttps://api.textzy.in/api/public/messages/send

Request Header Parameters

NameDescriptionMandatory
Content-Typeapplication/jsonY

Request Body Parameters

KeyTypeDescriptionMandatory
tenantSlugstringTenant slugY
userstringPublic API userY
pswdstringPublic API passwordY
apikeystringPublic API keyY
recipientstringMobile number with country codeY
messagestringApproved DLT messageY
senderstringDLT sender IDY
peIdstringDLT PE IDY
templateIdstringDLT template IDY
idempotencyKeystringOptional de-duplication keyN
SMS validation requirements
tenantSlug, user, pswd, and apikey must belong to the same tenant.
recipient must include country code without spaces, for example 919999999999.
sender, peId, and templateId must match your approved DLT configuration.
message must exactly match the registered DLT template content except allowed variables.

Common SMS Error Codes

HTTPCodeMeaningWhat to check
400validation_errorRequired field is missing or malformedCheck `recipient`, `sender`, `peId`, `templateId`, and payload field names
401invalid_public_credentialsTenant public API auth failedVerify `tenantSlug`, `user`, `pswd`, and `apikey`
403public_api_disabledTenant public API is disabledEnable public API for the tenant in platform settings
409duplicate_requestSame idempotency key already processedRetry with a new `idempotencyKey` only when needed
422dlt_rejectedDLT registration data did not matchRecheck sender ID, PE ID, template ID, and final message body
cURL ExampleSMS Send
curl --request POST \
  --url https://api.textzy.in/api/public/messages/send \
  --header 'accept: application/json' \
  --header 'content-type: application/json' \
  --data '{
    "tenantSlug":"moneyart",
    "user":"MONEYART",
    "password":"YOUR_PASSWORD",
    "apiKey":"YOUR_API_KEY",
    "channel":"sms",
    "recipient":"919999999999",
    "message":"Your approved DLT message",
    "sender":"MNYART",
    "peId":"1601100000000006533",
    "templateId":"1207171593687982329"
  }'
200 OKAccepted for processing
{"jobId":"GUID","message":"Accepted"}

DigiLocker KYC

Create a KYC session and redirect the user to DigiLocker for consent, document access, and verification.

GEThttps://api.textzy.in/api/public/kyc/sessions/start

Query Parameters

KeyTypeDescriptionMandatory
tenantSlugstringTenant slugY
userstringPublic API userY
pswdstringPublic API passwordY
apikeystringPublic API keyY
providerstringMust be digilockerY
docTypestringAADHAAR, PAN, DLY
customerRefstringYour reference for trackingN
successRedirectUrlstringRedirect after successN
failureRedirectUrlstringRedirect after failureN
webhookUrlstringWebhook for result deliveryN
Accepted docType
AADHAAR
Accepted docType
PAN
Accepted docType
DL
DigiLocker accepted doc types
AADHAAR for Aadhaar-based KYC, PAN for PAN verification, and DL for driving licence verification.
Send only one docType per session request.

Common DigiLocker Error Codes

HTTPCodeMeaningWhat to check
400invalid_doc_type`docType` is not supportedUse only `AADHAAR`, `PAN`, or `DL`
401invalid_public_credentialsTenant public API auth failedVerify `tenantSlug`, `user`, `pswd`, and `apikey`
403provider_not_enabledDigiLocker is not enabled for the tenantEnable DigiLocker in tenant/platform settings
409session_already_existsSession conflicts with an existing active requestUse a fresh `customerRef` or wait for prior session completion
502digilocker_upstream_errorDigiLocker partner API returned an upstream failureRetry later and inspect provider response in platform report
cURL ExampleDigiLocker KYC
curl --request GET \
  --url 'https://api.textzy.in/api/public/kyc/sessions/start?tenantSlug=moneyart&user=MONEYART&pswd=YOUR_PASSWORD&apikey=YOUR_API_KEY&provider=digilocker&docType=AADHAAR&customerRef=test-001'
200 OKSession created
{"sessionId":"GUID","provider":"digilocker","status":"created","docType":"AADHAAR","redirectUrl":"https://digilocker...","state":"..."}

  --url 'https://api.textzy.in/api/public/kyc/sessions/GUID?tenantSlug=moneyart&user=MONEYART&pswd=YOUR_PASSWORD&apikey=YOUR_API_KEY&includeBase64=true'
200 OKSession result
{"sessionId":"GUID","status":"verified","provider":"digilocker","result":{"documents":[...]}}
Status endpoint error codes
401 invalid_public_credentials when tenant public auth fails.
404 session_not_found when the session ID does not exist for that tenant.
410 session_expired when the KYC session is no longer valid.
500 internal_error when the provider result cannot be read or transformed.

KYC File Download

Download a specific KYC document file by session and file identifier when file payloads are available.

GEThttps://api.textzy.in/api/public/kyc/sessions/{sessionId}/files/{fileId}
Use the status endpoint first to discover available file identifiers and file metadata before downloading.
File download error codes
401 invalid_public_credentials when tenant public auth fails.
404 file_not_found when the file id is not present for that session.
422 file_payload_missing when provider metadata exists but file content is unavailable.
502 provider_file_fetch_failed when the upstream document fetch fails.
